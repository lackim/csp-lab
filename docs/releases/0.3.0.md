# csp-lab 0.3.0

Test your own CSP application in Docker with real libcsp traffic, rather than
checking only the built-in ping nodes.

- Add up to eight immutable `Node(address, image)` configurations to `Lab` or
  the pytest marker. Local images are reused; missing images are pulled before
  startup. Restart retains the original container and image ID.
- `Lab.request()` sends one raw packet and returns one `bytes` reply, including
  an empty reply. `RequestTimeout` distinguishes no reply from application data.
  Ports are 10–63, payloads 0–256 bytes, and network timeouts 100–10000 ms.
- Failed startup, contexts, and pytest tests retain bounded manifests and service
  logs before teardown, including shared labs. Capture can be disabled.
- One-off probes have explicit ownership, deadline/cancellation cleanup, and
  scoped recovery after a killed worker. Uncertain removal disables the lab.
- Build-time bounds guards reject oversized ZMQ frames before managed packet
  copies, including the hub diagnostic path. libcsp remains pinned at v2.1.

The [standalone C example](../../examples/custom-node/README.md) includes CSP v1/v2
pytest tests and an intentionally broken image: ping succeeds while the same
application assertion fails. CI also covers binary boundaries, one-send timeout
semantics, restart/isolation, artifacts, native canaries, and AddressSanitizer.

Use package and native image version 0.3.0 together. Earlier images lack request
mode. CLI state and MCP diagnostic operations continue to use the demo nodes;
diagnose JSON additionally includes an `imageIds` mapping (empty for the demo).

Timeout does not prove that the application did not execute a request. There are
no automatic retries or added application headers; include your own correlation
ID when needed. Manifests exclude payloads and exception text; service logs are
verbatim and may contain application data. See the example for limits and opt-out.
